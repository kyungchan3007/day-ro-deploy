# 웹 접근성 구현 지침

## 목적
- 모든 UI/마크업/인터랙션 변경에서 웹 접근성을 기본 요구사항으로 강제한다.
- 에이전트가 디자인 구현만 하고 접근성을 놓치는 일을 막는다.

## 적용 범위
다음 중 하나라도 해당하면 이 문서를 반드시 먼저 읽고 반영한다.

- HTML/JSX 마크업 수정
- 버튼, 링크, 입력, 다이얼로그, 드로어, 탭, 아코디언, 메뉴, 카드 등 인터랙션 UI 추가/수정
- 페이지/화면/위젯 레이아웃 수정
- 폼 추가/수정
- 모달/토스트/오버레이/포털 UI 추가/수정
- 라우팅 진입점, 내비게이션, 뒤로가기, 포커스 이동 변경
- e2e/단위 테스트에서 사용자 상호작용 검증 추가

## 절대 원칙
- 시맨틱 HTML을 우선한다. `div`로 버튼/링크/리스트/헤딩을 흉내 내지 않는다.
- 클릭 가능하면 `button` 또는 `a`/`Link`를 사용한다.
- 이동은 링크, 동작은 버튼으로 구분한다.
- placeholder는 label을 대체하지 않는다.
- 색상만으로 상태를 전달하지 않는다.
- 키보드만으로 모든 핵심 기능이 가능해야 한다.
- 스크린리더 사용자에게 현재 상태와 목적이 전달되어야 한다.
- 가짜 링크(`href="#"`)와 가짜 버튼을 만들지 않는다.

## 마크업 기준

### 랜드마크
- 페이지에는 적절한 랜드마크를 둔다: `header`, `nav`, `main`, `footer`, 필요 시 `aside`, `section`.
- `nav`에는 목적을 설명하는 `aria-label`을 붙인다.
- 한 페이지의 주요 제목은 가능한 한 하나의 `h1`로 유지한다.

### 헤딩
- 시각 스타일만 큰 텍스트를 만들지 말고 실제 `h1`~`h6` 계층을 쓴다.
- 헤딩 레벨은 순서를 건너뛰지 않는 것을 원칙으로 한다.

### 리스트
- 반복 목록은 `ul/ol/li`를 사용한다.
- 카드 목록, 메뉴 목록, 검색 결과, 저장 목록을 `div` 나열로 만들지 않는다.

## 인터랙션 기준

### 링크와 버튼
- 페이지 이동: `Link`/`a`
- 현재 페이지 내 상태 변경, 제출, 토글, 모달 열기: `button`
- 버튼/링크에 텍스트가 없으면 `aria-label`을 제공한다.

### 선택 컨트롤
- 단일 선택은 가능하면 네이티브 `radio`, 복수 선택은 `checkbox`를 우선한다.
- 커스텀 UI를 쓰더라도 의미 구조는 `radiogroup/radio`, `checkbox`, `switch` 등으로 유지한다.
- `aria-pressed`는 토글 버튼일 때만 사용하고, 체크박스/라디오 대체용으로 남용하지 않는다.

### 폼
- 모든 입력에는 대응하는 `label` 또는 동등한 이름 계산 경로(`aria-label`, `aria-labelledby`)가 있어야 한다.
- 관련 입력 그룹은 `fieldset/legend`로 묶는다.
- 필수값은 시각 표시뿐 아니라 의미도 전달해야 한다.
- 에러 메시지는 입력과 연결한다. 가능하면 `aria-describedby`, `aria-invalid`를 사용한다.

### 다이얼로그/드로어
- `role="dialog"` 또는 적절한 네이티브 구조를 사용한다.
- `aria-modal="true"`를 제공한다.
- 제목은 `aria-labelledby`로 연결하고, 설명이 있으면 `aria-describedby`로 연결한다.
- 열릴 때 포커스를 내부로 이동한다.
- 닫힐 때 포커스 복귀 지점을 고려한다.
- `Esc` 닫기와 탭 포커스 순환을 지원한다.

## 상태 전달 기준
- 로딩, 선택됨, 비활성, 진행률, 완료, 오류를 텍스트/속성으로도 전달한다.
- 진행 상태는 `progressbar` 또는 적절한 상태 텍스트를 사용한다.
- 아이콘만으로 의미를 전달하지 않는다. 장식 아이콘은 `aria-hidden="true"`를 고려한다.

## 이미지 기준
- 장식 이미지는 빈 `alt=""`
- 의미 있는 이미지는 맥락에 맞는 `alt`
- 이미지를 링크/버튼 안에 넣을 때 텍스트 이름 계산이 충분한지 확인한다.

## 포커스 기준
- `focus-visible` 스타일을 제거하지 않는다.
- 키보드 포커스가 배경 오버레이 뒤로 빠지지 않게 한다.
- 라우트 전환이나 상태 전환 후 포커스 손실이 없도록 주의한다.

## 금지 사항
- `href="#"`
- 클릭 핸들러만 있는 `div`, `span`
- label 없는 입력
- 제목 없는 dialog
- 스크린리더 이름 없는 아이콘 버튼
- 선택 UI를 전부 색상 변화로만 표현

## 구현 체크리스트
- 역할이 맞는 태그를 썼는가
- 페이지에 `main`과 적절한 제목 구조가 있는가
- 반복 UI가 리스트로 마크업돼 있는가
- 입력에 label이 있는가
- 그룹 입력에 `fieldset/legend`가 있는가
- 링크와 버튼의 역할이 섞이지 않았는가
- 다이얼로그/드로어에 제목, 포커스 이동, `Esc` 닫기가 있는가
- 키보드만으로 핵심 동작을 끝낼 수 있는가
- 상태가 텍스트/속성으로도 전달되는가
- 가짜 링크/가짜 버튼이 없는가

## 테스트 기준
- 단위 테스트는 public API와 관찰 가능한 접근성 계약을 본다.
- 가능하면 `getByRole`, `getByLabelText`, `getByText` 순서로 접근한다.
- e2e는 키보드 포커스 이동, dialog 열림/닫힘, 버튼 이름, 현재 step/진행 상태를 검증한다.
- 스냅샷보다 역할과 이름 기반 assertion을 우선한다.

## 검증 기준
- 접근성은 “추가 품질”이 아니라 기본 완료 조건이다.
- 시맨틱/키보드/이름 계산이 깨져 있으면 구현 완료로 보지 않는다.
- 디자인 시안에 정보가 없더라도 접근성 필수 속성은 에이전트가 보완해야 한다.
