## 2026-09-08-course-loading-cls-vitals
- domain: course-situation, home
- 의도: `/course/new` 성능 점검 중 발견한 로딩 화면 CLS 제거 + Web Vitals 계측을 여러 화면에서 재사용 가능하게 일반화.
- 결정: 로딩 "코스 보러 가기" CTA를 조건부 렌더(`{ready && <Button/>}`)에서 **항상 렌더 + `disabled={!ready}`**(완료 시 삽입이 아닌 활성화 전이)로 바꿔 layout shift 제거 — 준비 판정/이동 로직은 `useSituationFlowController`/`useCourseGeneration`에 유지, UI는 바인딩만. dev 전용 `WebVitalsLogger`(`route` 파라미터, prod no-op, `reportAllChanges`)를 `shared/observability`로 신설하고, `/course/new`는 스텝(`?step=`) 전환에도 유지되도록 page가 아닌 layout에 마운트. 홈 계측을 shared 로거로 통합하고 홈 전용 `HomeWebVitalsLogger` 제거(shared 승격 = home·course/new 2곳 사용으로 정당화).
- 근거/제약: CTA는 준비 전후 크기/DOM이 동일해야 함(disabled는 opacity/pointer-event만 변경) — 완료 시 재삽입 금지가 CLS 회귀 방지 핵심. 계측은 dev 전용·prod no-op 유지(서버 layout이 `NODE_ENV` 가드로 client leaf 렌더, 직렬화 가능한 `route` 문자열만 전달). CTA가 항상 렌더되므로 e2e는 `toBeEnabled()`로 준비 상태를 기다려야 함(`toBeVisible` 사용 금지). LCP 3.3s(폰트 의심)는 out of scope — 후속 tasks.
- 검증: approved_with_notes (reports/validation/2026-09-08-course-loading-cta-cls.md, run: reports/runs/2026-09-08-course-loading-cta-cls.md). tsc/eslint 0, 단위 4, e2e 4 통과(Codex 샌드박스 차단 → Claude가 dev 머신에서 재실행). 후속: `e2e-impact-map.json`에 `course-loading-quiz.spec.ts` 추가, 네트워크 환경에서 `npm run build` 재확인.
