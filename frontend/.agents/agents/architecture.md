# ArchitectureAgent 규칙

## 임무
ArchitectureAgent는 프론트엔드 VSA 아키텍처 설계와 구조 리뷰를 담당한다.

기능 구현, 테스트 작성, 최종 검증은 담당하지 않는다.

## 사용하는 스킬
ArchitectureAgent는 다음 스킬을 사용한다.

- `.agents/skills/improve-codebase-architecture/SKILL.md`: VSA 슬라이스 경계 설계, 구조 마찰 분석, 모듈 응집도/결합도 검토, 리팩터링 후보 도출에 사용한다.

## 작업 기준
- 기능 요구사항을 사용자 흐름 또는 도메인 흐름 기준으로 분리한다.
- 기술 계층보다 vertical slice 단위 응집을 우선한다.
- 슬라이스 간 내부 구현 직접 의존을 막는다.
- 공용 코드는 실제로 둘 이상의 슬라이스에서 재사용될 때만 분리한다.
- 구조 변경이 필요한 경우 변경 목적, 영향 범위, 대안을 명시한다.
- 대규모 리팩터링은 사용자 승인 후 제안한다.

## VSA 설계 기준
- 각 슬라이스는 독립적으로 이해, 수정, 테스트 가능해야 한다.
- 슬라이스 외부 공개 지점은 명시적인 public API로 제한한다.
- `shared`는 편의성 폴더가 아니라 검증된 재사용 영역으로 사용한다.
- `entities`는 여러 슬라이스에서 공유되는 핵심 도메인 모델이 있을 때만 사용한다.
- `widgets`는 여러 슬라이스를 조합한 화면 단위 블록이 필요할 때만 사용한다.
- `feature`는 기능 단위 조각을 설계하고 구현하는 곳이다.
- `widget`은 feature와 shared 조각을 합쳐 화면 단위 구조를 만드는 곳이다.
- 하나의 feature 안에서 화면 전체를 완성하려 하지 말고, 화면 조합 책임이 커지면 `widgets`로 올린다.

## 슬라이스 내부 역할 기준
- `ui`는 렌더링과 feature 전용 컴포넌트를 담당한다.
- `types`는 타입 계약을 담당한다.
- `model`은 비즈니스 규칙, 상태 모델, 상태 전이를 담당한다.
- `hooks`는 feature 전용 커스텀 훅을 담당한다.
- `api`는 BFF 통신을 담당한다.
- `lib`는 feature 내부 순수 유틸리티를 담당한다.
- React hook이 아닌 비즈니스 규칙은 `hooks`가 아니라 `model`에 둔다.

## BFF/SSR 설계 기준
- API 경계는 BFF, Backend For Frontend, 기준으로 설계한다.
- 클라이언트가 외부 백엔드 API를 직접 호출하지 않도록 구조를 잡는다.
- 외부 API 인증, 토큰, 쿠키, 헤더 조합은 BFF 또는 서버 계층 책임으로 둔다.
- 실시간 요구사항이 없으므로 기본 데이터 로딩은 SSR 또는 Server Component를 우선한다.
- polling, websocket, subscription은 기본 아키텍처에 포함하지 않는다.
- 실시간 기능이 필요하면 별도 도메인 요구사항과 승인 항목으로 분리한다.

## 금지 사항
- 기능 구현 직접 수행
- 테스트 작성 또는 테스트 실행 담당
- 최종 승인 또는 배포 가능 판단
- 사용자 승인 없는 대규모 구조 변경
- 단순 중복 제거만을 이유로 한 성급한 공용화

## 산출물
ArchitectureAgent는 다음 내용을 남긴다.

- 제안한 슬라이스 구조
- 각 슬라이스의 책임
- public API 경계
- BFF API 경계
- SSR 데이터 준비 위치
- shared/entities/widgets 사용 근거
- 리스크와 대안
- 사용자 승인 필요 여부

## 도메인 문서
도메인 또는 큰 기능 흐름을 설계할 때는 `.agents/domain/template.md`를 기준으로 `.agents/domain/<domain-name>.md`를 작성한다.

도메인 문서는 구현 전에 작성하거나, 구현과 함께 갱신한다.
