# 04. 성능 최적화

> "측정 → 원인 분석 → 개선 → 재측정" 순서로 진행하고, 개선 결과는 CI 번들 예산으로 고정합니다.

## ① 코스 추천 중복 요청 제거 (#97)

- **배경** — 로딩 화면에서 받은 추천 결과를 결과 화면에서 서버가 다시 요청
- **해결** — 로딩 단계 응답을 결과 단계로 넘기고, 넘겨받은 값이 없을 때만 서버 요청
- **해결** — 홈 계정 메뉴의 세션 조회를 첫 렌더가 아닌 메뉴 열기 시점으로 지연
- **결과** — 코스 결과 진입 시 추천 요청 1회 감소, 홈 첫 진입 `/api/auth/me` 호출 제거

## ② Web Vitals 계측 · 홈 LCP · TTFB 개선 (#99)

- **배경** — 개선 효과를 수치로 확인할 계측 수단 부재
- **해결** — `useReportWebVitals` + attribution으로 LCP · INP · CLS · FCP · TTFB와 LCP 원인 계측
- **해결** — 첫 카드 이미지 preload · 높은 fetch priority, 홈 이미지 webp 재압축
- **결과** — 홈 이미지 합계 14,154B → 6,170B (-56.4%)
- **결과** — 개발 환경 LCP 448ms → 124ms (-72.3%), TTFB 360.3ms → 36.3ms
- **결과** — 프로덕션 빌드에서 홈 정적 사전 렌더링 확인

## ③ 로딩 화면 CLS 제거 · 코드 분할 (#115)

- **배경** — AI 완료 시 "코스 보러 가기" 버튼이 새로 삽입되며 퀴즈 카드를 밀어냄 (프로덕션 Lighthouse CLS 0.159)
- **해결** — 버튼을 처음부터 렌더하고 `disabled`로 대기, 완료 시 활성화만 전환
- **해결** — 무거운 화면 코드를 `next/dynamic`으로 분할
- **결과** — 로딩 완료 시 layout shift 제거, `/course/new` 초기 전송량 384 → 361KiB
- **확인 필요** — LCP 3.3s는 범위 밖 (폰트 원인 의심 → ④에서 처리)

## ④ 번들 감량 · 회귀 가드 (#119)

- **배경** — 브라우저 응답 검증용 zod classic 전체가 11개 라우트 첫 로드에 포함, 미사용 Mono 폰트 preload
- **해결** — zod classic → zod/mini 전환(네임스페이스 import), 미사용 폰트 제거
- **해결** — ESLint로 zod classic import 차단, 라우트별 첫 로드 JS 예산 스크립트를 CI에 추가
- **결과** — zod 청크 270,924B → 43,262B, 라우트 첫 로드 JS 약 -245KB (`/course/new` 913,599B → 668,496B)
- **결과** — 폰트 요청 2개(52KiB) → 1개(29KiB), 모바일 Lighthouse Performance 93 → 95 · LCP 3.2s → 2.9s
- **검증** — classic · mini 동작 동등성 312건 비교 통과

## 회귀 방지

- **번들 예산** — 라우트별 기준 + max(10KiB, 2%) 초과 · 라우트 누락 시 CI 실패 (`scripts/check-route-bundle-budget.mjs`)
- **새 라우트 추가 시** — 기준 파일(`scripts/route-bundle-baseline.json`)에 측정값 등록 필요
